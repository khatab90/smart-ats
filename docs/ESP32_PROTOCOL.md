# Smart ATS — ESP32 ↔ Supabase protocol v1

The board talks HTTPS to Supabase PostgREST RPC endpoints:

- Base URL: `https://<project>.supabase.co/rest/v1/rpc/<function>`
- Headers on every call: `apikey: <anon key>`, `Authorization: Bearer <anon key>`, `Content-Type: application/json`.
- The board authenticates with its own secret `token` (from `register_device`), sent as a parameter.
- **Never** embed the service-role key in firmware.

## 1. `device_ingest` — telemetry + events (every `interval_ms`, e.g. 2 s)

```json
{ "p_device_id": "ATS-000123", "p_token": "<token>", "p_payload": { ... } }
```

Payload fields (`null` = no reading; never send 0 for a missing sensor):

| field | type | meaning |
|---|---|---|
| `v` | 1 | protocol version (required) |
| `seq` | int | telemetry sequence, monotonic per boot |
| `ts` | ISO-8601 UTC | board RTC/NTP time (omit if the clock is not set) |
| `interval_ms` | int | reporting interval; the app marks data stale after ~3 intervals |
| `fw` | string | firmware version |
| `mode` | `smart` \| `manual` | |
| `mode_since` | ISO | |
| `state` | `normal` \| `transferring` \| `no_source` \| `lockout` | |
| `active` | `grid` \| `solar` \| `generator` \| null | source feeding the load (null in `no_source`) |
| `active_since` | ISO | |
| `sources.<id>` | object | `{ v, f, available, qualified, q_elapsed_s, q_required_s, reason }` |
| `load` | object | `{ v, a, w, f }` measured on the load side |
| `contactors.<id>` | object | `{ cmd, fb }` commanded vs auxiliary-contact feedback |
| `alarms` | string[] | e.g. `interlock_mismatch`, `transfer_lockout`, `sensor_fault`, `over_temperature`, `inverter_fault`, `generator_alarm` |
| `override` | object \| null | `{ active, at, reason, requested }` when protection overrode a manual choice |
| `config_version` | int | settings version currently applied |
| `controller` | object | `{ uptime_s, reset_reason, temp_c, supply_v }` |
| `rssi` | int | dBm |
| `energy_wh.<id>` | number | **cumulative, non-volatile** Wh counter per source |
| `runtime.<id>` | object | `{ s, since }` non-volatile seconds counted only while the source feeds the load |
| `events` | array | buffered events, see §2 |

`sources.<id>.reason` values:

- `no_voltage`, `undervoltage`, `overvoltage`, `underfrequency`, `overfrequency`
- `qualifying`, `standby` (stopped generator, healthy and ready to start: selectable for manual and Smart transfers), `failed_to_start`, `locked_out`, `inverter_fault`, `sensor_fault`
- `not_installed` (the app hides these sources)

Response:

```json
{ "ok": true, "server_time": "...", "settings_version": 4,
  "commands": [{ "id": "uuid", "type": "set_mode", "payload": { "mode": "manual" }, "expires_at": "..." }] }
```

- If `settings_version > config_version`, call `device_get_settings`.
- Validate the settings, apply them, then report the new `config_version` and a `settings_applied` (or `settings_rejected`) event.
- Commands are re-delivered until acknowledged or expired. De-duplicate them by `id`.

## 2. Events

```json
{ "seq": 1201, "ts": "...", "type": "transfer_completed", "severity": "info",
  "source": null, "from": "grid", "to": "solar",
  "data": { "reason": "undervoltage", "mode": "smart",
            "detect_ms": 2004, "open_ms": 42, "dead_ms": 1003, "close_ms": 38 } }
```

- `seq` must be unique per device and persist across reboots (e.g. stored in NVS). The server ignores duplicates, so buffered events can be replayed safely after a disconnection.
- Types:
  - `source_lost` with `data.was_active` and `data.reason`; `source_restored`
  - `transfer_started`, `transfer_completed`, `transfer_failed` with `data.reason`
  - `no_source_started` with `data.<source> = reason`; `no_source_ended`
  - `electrical_fault` with `data.kind` ∈ `undervoltage|overvoltage|underfrequency|overfrequency` and `data.value`; `electrical_fault_cleared`
  - `interlock_fault`, `transfer_lockout`, `protection_override`, `mode_changed`, `controller_restarted`
  - `settings_applied`, `settings_rejected`, `runtime_reset`

The server maps events to user notifications:

| notification | events |
|---|---|
| source outage (critical, cannot be muted) | `source_lost` with `was_active=true`, `no_source_started` |
| transfer | `transfer_completed` |
| electrical fault | `electrical_fault`, `transfer_lockout` |
| board connection lost | generated by the server watchdog after 30 s without telemetry |
| transfer failure (critical, cannot be muted) | `transfer_failed`, `interlock_fault` |

## 3. `device_get_settings`

`{ "p_device_id", "p_token" }` returns the full settings row:

- `version`, `priority`
- `nominal_voltage`, `nominal_frequency`
- trip/recover thresholds in **% of nominal** with their delays
- `return_delay_s`, `min_dwell_s`, `rate_limit_count`, `rate_limit_window_min`
- `neutral_delay_ms`, `transfer_timeout_ms`
- `gen_crank_attempts`, `gen_warmup_s`, `gen_cooldown_s`
- capacities, `max_current_a`, `manual_revert_min`, `timezone`

The board must not run Smart switching while `nominal_voltage` or `nominal_frequency` is null.

## 4. `device_ack_command`

`{ "p_device_id", "p_token", "p_command_id", "p_status", "p_result" }` where `p_status` ∈ `accepted | executing | completed | rejected | failed`.

- Acknowledge `accepted` (or `rejected` with `{ "reason": "..." }`) within **10 s**.
- Long actions (generator crank + warm-up) report `executing`, then `completed` or `failed`.
- The app only reports success after `completed`.

Commands:

- `set_mode { mode }`
- `set_source { source }` — manual mode only. Refuse if the source is not qualified.
- `reset_runtime { sources: [...] }` — reset the non-volatile counters and set `since` to now.

## 5. Required board behaviour (reference: `tools/device-emulator/logic.mjs`)

- **Qualification:** a source trips after its delay outside the trip limits, and requalifies only inside the recover band, continuously for `return_delay_s`. Loss of voltage trips immediately.
- **Smart mode:** pick the first qualified source in `priority`. Respect `min_dwell_s` and the rate limit, except when leaving a failed source.
- **No valid source:** enter `no_source`, open all contactors, and stop the runtime and energy counters.
- **Transfer sequence:** open the old contactor → verify via feedback → wait `neutral_delay_ms` → re-check the target → close the new contactor. Report the measured timings.
- **Contactor mismatch:** latched `lockout` plus an `interlock_fault` event.
- **Generator:** crank up to `gen_crank_attempts` times, warm up before taking the load, and cool down unloaded after leaving it.
- **Manual mode:** protection still moves the load off a failed source and reports `override`. Revert to Smart after `manual_revert_min` if it is set.
- **While offline:** keep events in a ring buffer and send them in the next successful `device_ingest`.
- **Daily energy:** "today" is computed by the server from hourly buckets in the device `timezone`. Energy counters themselves are never reset.
