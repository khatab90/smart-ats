# إعداد Supabase لتطبيق Smart ATS

التطبيق لا يحتوي أي بيانات تجريبية. كل ما يعرضه يأتي من Supabase، وكل القراءات والحالات تأتي من بورد ESP32.

## 1. تشغيل ملف الترحيل (مرة واحدة)

1. افتح Supabase Dashboard ← مشروعك ← **SQL Editor** ← **New query**.
2. انسخ محتوى الملف `supabase/migrations/20261116000000_smart_ats_schema.sql` كاملاً والصقه، ثم **Run**.
3. الملف آمن لإعادة التشغيل. لا يضيف أي بيانات وهمية.

ما ينشئه الملف:

| الجدول | المحتوى |
|---|---|
| `profiles` | بيانات المستخدم (البريد والهاتف الموثّقان يُنسخان من Supabase Auth) |
| `devices` / `device_secrets` | الأجهزة بمعرّف المصنع، وأسرارها (رمز الجهاز وPIN مشفّرين ولا تقرأهما الواجهة) |
| `device_members` | من يحق له الوصول لكل جهاز ودوره (مسؤول / مشاهد) |
| `device_status` | آخر حالة أرسلها البورد |
| `telemetry` | القراءات الخام للرسم اللحظي (تُحذف بعد 3 أيام) |
| `energy_hourly` | تجميع ساعي لعدادات الطاقة لكل مصدر |
| `events` | سجل أحداث موحّد ومرقّم لكل جهاز |
| `device_settings` | إعدادات الجهاز مع رقم إصدار |
| `device_commands` | أوامر التحكم ودورة حياتها |
| `invitations` | الدعوات (رابط لمرة واحدة، صالح 72 ساعة) |
| `notifications` / `notification_preferences` | الإشعارات وتفضيلات التنبيه |

- **RLS مفعّل على كل الجداول**. المستخدم يرى فقط الأجهزة التي هو عضو فيها، والكتابة الحساسة تتم عبر دوال تتحقق من الدور.
- مفتاح Service Role غير مستخدم في الواجهة إطلاقاً.

## 2. المهام المجدولة (pg_cron)

مراقب نبضة الحياة يحوّل الجهاز إلى «غير متصل» بعد 30 ثانية من توقف البيانات ويرسل إشعار «انقطاع الاتصال بالبورد».

- فعّل **Database ← Extensions ← pg_cron**. إذا لم يكن مفعّلاً قبل تشغيل الملف، فأعد تشغيل الملف بعد تفعيله.
- بدونه يبقى التطبيق يعرض الجهاز «غير متصل» بعد 30 ثانية (يُحسب في الواجهة)، لكن **لن يُرسل إشعار** انقطاع الاتصال.

## 3. إعدادات المصادقة (Authentication)

1. **URL Configuration**:
   - ضع رابط التطبيق المنشور في **Site URL**.
   - أضفه مع رابط المعاينة في **Redirect URLs** (مثل `https://your-app.example/**`).
   - بدون ذلك لن تعمل روابط تأكيد البريد واستعادة كلمة المرور والدعوات.
2. **SMTP مخصص** (Authentication ← Emails ← SMTP Settings):
   - خادم البريد المدمج في Supabase يرسل فقط إلى عناوين أعضاء فريق المشروع، وبعدد محدود جداً.
   - تأكيد الحساب وتغيير البريد والدعوات تحتاج SMTP مخصصاً، مثل Resend أو SendGrid أو Amazon SES.
3. **قالب Magic Link**: الدعوات تُرسل كرابط دخول. يُنصح بتعديل نصه ليذكر أنه دعوة للانضمام إلى Smart ATS.
4. **التحقق من الهاتف**:
   - فعّل **Phone** provider واربطه بمزود SMS (مثل Twilio).
   - حتى يتم ذلك، يرفض التطبيق تغيير رقم الهاتف برسالة واضحة، ولا يحفظه دون تحقق.

## 4. تسجيل الأجهزة (خطوة المصنع)

كل بورد يُسجَّل مرة واحدة من SQL Editor (أو بمفتاح Service Role من أداة المصنع، وليس من التطبيق):

```sql
select public.register_device('ATS-000123');            -- جهاز إنتاج
select public.register_device('ATS-TEST01', 'test');     -- جهاز اختبار
```

الناتج يحتوي على قيمتين تظهران مرة واحدة فقط ولا يمكن استرجاعهما:

- `token`: يُخزَّن في البرنامج الثابت للبورد.
- `pin`: يُطبع على ملصق الجهاز (أو رمز QR).

يضيف المستخدم الجهاز من التطبيق بمعرّف الجهاز ورمز PIN، فيصبح مالكاً ومسؤولاً عنه.

## 5. بيئة الاختبار

- الأجهزة المسجلة بـ `environment = 'test'` لا تظهر ولا يمكن إضافتها في نسخة التشغيل.
- لتجربتها عيّن متغير البيئة `VITE_APP_ENV=test` في نسخة اختبار منفصلة.
- أداة محاكاة البورد الخارجية: `tools/device-emulator/emulator.mjs`. تعمل خارج التطبيق وتتصل بنفس واجهة البورد الحقيقي:

```bash
ATS_DEVICE_ID=ATS-TEST01 ATS_DEVICE_TOKEN=<token> ATS_TIME_SCALE=10 pnpm emulator
```

أوامرها: `grid off|on|low|high` و`solar off|on` و`gen fail|ok` و`offline 40` و`interlock on` و`load 3500`.

## 6. الاختبارات

```bash
pnpm test      # منطق التطبيق ومنطق الوضع الذكي في أداة المحاكاة
pnpm test:db   # يشغّل ملف الترحيل على PostgreSQL محلي (PGlite) ويختبر RLS والدوال
```
